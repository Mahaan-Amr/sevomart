# تحویل راه‌اندازی و تنظیمات فروشگاه

مرجع: [[ساخت] ساخت رابط راه‌اندازی و تنظیمات فروشگاه](https://github.com/Mahaan-Amr/sevomart/issues/142)

مبنای اجرا `73e0b7ab64ae8a003e786635c8b6fe2b7c5b40d4` و predecessor migration
`20260827120000__conversations__send-claims` است. این تغییر migration، dependency،
متغیر محیطی، پورت، runtime یا قرارداد producer تازه ندارد.

## مسیرها و رفتار

- مسیر راه‌اندازی متمرکز `/seller/store/setup` حفظ شده و تنظیمات مستقل
  `/seller/store/profile`، `/seller/store/shipping`، `/seller/store/returns` و
  `/seller/store/appearance` به وضعیت فروشگاه متصل شده‌اند.
- معرفی فروشگاه شامل نام، شناسه لینک و معرفی کوتاه است. دسترس‌پذیری شناسه هنگام
  خروج از ورودی بررسی می‌شود و پاسخ قدیمی شبکه نمی‌تواند نتیجه تازه را بازنویسی کند.
- ارسال از سه روش پست، پیک و دریافت حضوری پشتیبانی می‌کند. هر روش مستقل فعال یا
  غیرفعال می‌شود و عنوان، هزینه و زمان تحویل خودش را نگه می‌دارد. رقم فارسی و
  انگلیسی پذیرفته و مبلغ تومان پیش از ارسال به قرارداد IRR تبدیل می‌شود.
- سیاست مرجوعی در صفحه مستقل با متن روشن درباره حدود مسئولیت سوو و مسیر بعدی
  خریدار ویرایش می‌شود.
- ظاهر فروشگاه رنگ، لوگو و تصویر روی جلد را با پیش‌نمایش زنده و خطای فایل کنار
  همان ورودی مدیریت می‌کند. همین رفتار در «ذخیره و خروج» راه‌اندازی نیز برقرار است.
- پیام آمادگی انتشار کمبودهای واقعی روش ارسال، مرجوعی، شناسه لینک و مقصد تسویه را
  نام می‌برد. مرز producer تیکت #130 رعایت شده است: فقط وضعیت آزمایشی
  `TEST / TEST_VERIFIED` نمایش داده می‌شود و ادعای تأیید حساب بانکی واقعی وجود ندارد.

## شواهد

- `format:check`، lint و بررسی معماری، typecheck کل workspace و build تولیدی Next.js
  سبز هستند.
- unit برابر `111/111`، contract برابر `140/140` و integration برابر `157/157`
  روی PostgreSQL و MinIO ایزوله سبز هستند.
- سناریوی اختصاصی فروشگاه در چهار viewport برابر `4/4` سبز است و RTL، نبود overflow،
  keyboard focus، اندازه هدف، کنتراست، reduced motion، ذخیره و reload هر تنظیم،
  چند روش ارسال، رقم فارسی، رقابت پاسخ شناسه، خطای فایل کنار ورودی و پیام دقیق
  آمادگی انتشار را بررسی می‌کند.
- اجرای کامل E2E تعداد `168/180` تست را سبز کرد. هر چهار اجرای سناریوی این Issue سبز
  بودند؛ ۱۲ شکست یکسان در سه سناریوی قدیمی `release-critical-tracers`،
  `seller-application` و `store-following` رخ دادند. اولی و سومی projection عمومی را
  پیدا نکردند و دومی، به‌دلیل نبود دسترسی فروشنده در fixture، پیش از فرم به وضعیت
  درخواست تأییدشده رفت. diff این Issue producer کشف، درخواست فروشندگی یا gate دسترسی
  را تغییر نمی‌دهد.
- مرور مستقل Standards و Spec بدون finding قابل اقدام پایان یافت. تنها نکته غیرمسدودکننده
  اندازه فایل `store-builder.tsx` بود؛ بازآرایی گسترده خارج از محدوده این Issue نگه
  داشته شد.
