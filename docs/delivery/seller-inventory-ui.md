# تحویل رابط مستقل مدیریت موجودی فروشنده

مرجع: [[ساخت] ساخت رابط مستقل مدیریت موجودی فروشنده](https://github.com/Mahaan-Amr/sevomart/issues/145)

مبنای نهایی اجرا `1cad113c37974bc5b5abf8ff57ffac5cb70b4ea0` و predecessor migration
`20260830113000__identity-access__audit-unresolved-sensitive-attempts` است. این تغییر
migration، dependency، متغیر محیطی، پورت یا قرارداد producer تازه ندارد.

## رفتار تحویل‌شده

- مسیر canonical `/seller/inventory` فهرست خصوصی گونه‌ها و موجودی واقعی، رزروشده و
  قابل‌فروش را از `Inventory.v1` می‌خواند؛ صفحه‌بندی producer را تا پایان دنبال می‌کند
  و پاسخ را cache نمی‌کند.
- نام ویژگی گونه در adapter نمایشی دامنه کالا ساخته می‌شود. برای کالای منتشرشده،
  snapshot عمومی منتشرشده بر working copy خصوصی تقدم دارد تا ویرایش منتشرنشده به
  فضای عملیاتی موجودی نشت نکند؛ خواندن seller product فقط fallback کالای فاقد نمای
  عمومی است. بنابراین جست‌وجوی محلی نام کالا و ویژگی بدون گسترش قرارداد producer
  موجودی کار می‌کند.
- افزایش، کاهش و اصلاح مقدار مقصد با reason code مصوب و توضیح اختیاری به batch
  ممیزی‌شده موجودی فرستاده می‌شود و انتخاب دلیل صریحاً الزامی است. ورودی عدد صحیح
  فارسی، عربی یا لاتین را می‌پذیرد و کاهش به زیر صفر پیش از write با قدم اصلاح روشن
  متوقف می‌شود. در نتیجه مبهم، ویرایش و ساخت درخواست تازه قفل می‌شود؛ فروشنده فقط
  می‌تواند همان payload را با همان کلید idempotency پیگیری کند یا با تازه‌سازی، نتیجه
  authoritative را تطبیق دهد.
- همه خطاهای typed قرارداد موجودی به متن و اقدام بازیابی محلی فارسی نگاشت شده‌اند؛
  متن producer مستقیماً به کاربر نمایش داده نمی‌شود. پس از تعارض revision، تازه‌سازی
  مقدار authoritative را جایگزین می‌کند و فروشنده می‌تواند دوباره ثبت کند.
- رابط یک کار اصلی دارد، در موبایل به فهرست تک‌ستونه تبدیل می‌شود، targetهای اصلی
  حداقل ۴۰ پیکسل‌اند، نام دسترس‌پذیر هر عمل شامل کالا و گونه است و focus مرئی و
  `prefers-reduced-motion` پایه محصول حفظ می‌شوند.

## seam و شواهد آزمون

- unit در seam مدل ورودی و جست‌وجو: اعداد فارسی/عربی/لاتین، رد عدد منفی/اعشاری و
  ناامن، محاسبه سه عمل، جلوگیری از مقدار منفی، یکسان‌سازی حروف فارسی، حفظ کلید
  idempotency در retry و نگاشت کامل خطاهای typed.
- unit در adapter نمایش کالا: استخراج برچسب گونه از snapshot منتشرشده و working copy
  چندگونه‌ای، و برچسب دسته‌خنثی «گونه اصلی» برای کالای ساده.
- unit در seam گذرگاه HTTP وب: عبور query صفحه‌بندی/فیلتر، payload و کلید
  idempotency، `no-store` و رد مسیر تو در تو.
- E2E متصل به PostgreSQL در عرض‌های ۳۶۰، ۳۹۰، ۷۶۸ و ۱۴۴۰: ورود فروشنده فعال، کالای
  ساده ناموجود، متن و ویژگی بلند، تقدم snapshot منتشرشده، جست‌وجوی نام/ویژگی، انتخاب
  صریح دلیل، افزایش با عدد فارسی و keyboard، تعارض revision و recovery، رد موجودی
  منفی، قطع پاسخ پس از write و retry با همان کلید، RTL، reduced motion، کنتراست، نبود
  overflow افقی و target لمسی.

## نتیجه بررسی نهایی

- `format:check`، lint، مرزبندی معماری و typecheck کامل مخزن پاس شدند.
- ۱۷۰ آزمون unit، ۱۵۲ آزمون contract و ۱۷۹ آزمون integration پاس شدند.
- سناریوی اختصاصی موجودی و tracer ساخت/انتشار کالا در چهار اندازه‌نما، در مجموع ۸ از
  ۸ حالت، پاس شدند.
- اجرای کامل E2E با دو worker، پایگاه تازه و پورت ایزوله، ۲۲۴ از ۲۲۴ حالت را پاس کرد.
  URL تست‌های API از پورت runtime ساخته می‌شود، fixtureهای builder و following شماره
  اختصاصی دارند و یک unit test یکتا بودن همه گروه‌های شماره را قفل می‌کند. baselineهای
  تصویری storefront نیز با اطلاعات اعتماد فعلی همگام شده‌اند.
- بازبینی نهایی دو محور Standards و Spec بدون یافته است.
