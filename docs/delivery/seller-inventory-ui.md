# تحویل رابط مستقل مدیریت موجودی فروشنده

مرجع: [[ساخت] ساخت رابط مستقل مدیریت موجودی فروشنده](https://github.com/Mahaan-Amr/sevomart/issues/145)

مبنای اجرا `c603e81b7d89e0ca4ab33c5d97257f6191884ef8` و predecessor migration
`20260830113000__identity-access__audit-unresolved-sensitive-attempts` است. این تغییر
migration، dependency، متغیر محیطی، پورت یا قرارداد producer تازه ندارد.

## رفتار تحویل‌شده

- مسیر canonical `/seller/inventory` فهرست خصوصی گونه‌ها و موجودی واقعی، رزروشده و
  قابل‌فروش را از `Inventory.v1` می‌خواند؛ صفحه‌بندی producer را تا پایان دنبال می‌کند
  و پاسخ را cache نمی‌کند.
- نام ویژگی گونه با بازاستفاده از خواندن مجاز جزئیات همان کالا ساخته می‌شود؛ بنابراین
  جست‌وجوی محلی نام کالا و ترکیب ویژگی، بدون گسترش قرارداد متعلق به producer موجودی،
  کار می‌کند.
- افزایش، کاهش و اصلاح مقدار مقصد با reason code مصوب و توضیح اختیاری به batch
  ممیزی‌شده موجودی فرستاده می‌شود. ورودی عدد صحیح فارسی، عربی یا لاتین را می‌پذیرد و
  کاهش به زیر صفر پیش از write با قدم اصلاح روشن متوقف می‌شود.
- `REVISION_CONFLICT`، تعارض موجودی رزروشده و حذف گونه متن فارسی و اقدام «گرفتن
  اطلاعات تازه» دارند. پس از تازه‌سازی، revision authoritative جایگزین می‌شود و
  فروشنده می‌تواند همان اصلاح را دوباره ثبت کند.
- رابط یک کار اصلی دارد، در موبایل به فهرست تک‌ستونه تبدیل می‌شود، targetهای اصلی
  حداقل ۴۰ پیکسل‌اند، نام دسترس‌پذیر هر عمل شامل کالا و گونه است و focus مرئی و
  `prefers-reduced-motion` پایه محصول حفظ می‌شوند.

## seam و شواهد آزمون

- unit در seam مدل ورودی و جست‌وجو: اعداد فارسی/عربی/لاتین، رد عدد منفی/اعشاری و
  ناامن، محاسبه سه عمل، جلوگیری از مقدار منفی، یکسان‌سازی حروف فارسی و استخراج
  برچسب ویژگی از خواندن seller product.
- unit در seam گذرگاه HTTP وب: عبور query صفحه‌بندی/فیلتر، payload و کلید
  idempotency، `no-store` و رد مسیر تو در تو.
- E2E متصل به PostgreSQL در عرض‌های ۳۶۰، ۳۹۰، ۷۶۸ و ۱۴۴۰: ورود فروشنده فعال،
  جست‌وجوی ویژگی، افزایش با عدد فارسی و keyboard، تعارض revision و recovery، رد
  موجودی منفی، RTL، reduced motion، نبود overflow افقی و target لمسی.
