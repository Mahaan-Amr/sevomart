# ADR-001: پشته فنی و شکل استقرار نسخه اول

## زمینه

سوو یک محصول موبایل‌محور فارسی با ورودی اصلی از لینک مستقیم فروشگاه و کالا است. مشاهده، کشف و افزودن به سبد نباید به نصب یا ورود وابسته باشد. در مقابل، سفارش، موجودی، پرداخت و اختلاف به تراکنش، ردپای ممیزی و کنترل دسترسی دقیق نیاز دارند.

نسخه اول را دو توسعه‌دهنده می‌سازند. معماری باید عملیات روزمره و تعداد اجزای زیرساخت را کم نگه دارد، کار موازی را با قرارداد روشن ممکن کند و به سرویس خارجی‌ای که دسترسی تجاری پایدار آن برای ایران تأیید نشده وابسته نباشد.

## گزینه‌ها

1. **وب واکنش‌گرا/PWA و modular monolith قابل‌انتقال:** یک client عمومی، API مستقل و زیرساخت داده کم‌تعداد؛ دسترسی مستقیم و انتشار سریع، با محدودیت برخی قابلیت‌های native.
2. **وب به‌همراه React Native/Flutter از ابتدا:** دسترسی بیشتر به قابلیت‌های دستگاه، اما دو سطح محصول، QA و توزیع برای تیم دو نفره.
3. **microservice و سرویس‌های managed خارجی:** استقلال استقرار و scale بیشتر، در برابر پیچیدگی توزیع‌شده و ریسک دسترسی، قرارداد و خروج داده در ایران.
4. **full-stack یکپارچه در Next.js:** شروع کوچک‌تر، اما آمیختگی presentation با منطق حساس دامنه و قرارداد ضعیف‌تر برای client آینده.

## تصمیم

نسخه اول با این baseline ساخته می‌شود:

- تحویل به‌صورت وب واکنش‌گرا و PWA، با فارسی و RTL از ابتدا؛ اپ native یا cross-platform جزو baseline نیست.
- monorepo تایپ‌اسکریپت با `pnpm workspace`، شامل `Next.js` برای web، یک `NestJS`/`Fastify` modular monolith برای REST API و یک worker process از همان codebase.
- REST/JSON نسخه‌دار و OpenAPI قرارداد client است. منطق دامنه، مجوزها و تغییر وضعیت در API می‌ماند، نه در component یا Server Action.
- `PostgreSQL` منبع حقیقت است؛ `Prisma` دسترسی نوع‌دار و migrationهای SQL قابل‌مرور را فراهم می‌کند.
- جست‌وجوی اولیه با full-text و `pg_trgm`، صف با `pg-boss` و به‌روزرسانی با SSE یا polling انجام می‌شود. Redis، broker و موتور جست‌وجوی جدا فقط پس از عبور یک شاخص اندازه‌گیری‌شده از SLO افزوده می‌شوند.
- رسانه در object storage سازگار با S3 و پشت adapter ذخیره می‌شود؛ دیسک کانتینر و PostgreSQL محل نگهداری فایل نیستند.
- `web`، `api` و `worker` به‌صورت Docker containerهای stateless روی یک ارائه‌دهنده داخل ایران مستقر می‌شوند. PostgreSQL مدیریت‌شده و object storage باید export، backup و restore آزموده داشته باشند. انتخاب نام ارائه‌دهنده تصمیم جداگانه عملیاتی است.
- GitHub Actions و GHCR برای همکاری، CI و توزیع image مجازند، اما production باید با image استاندارد، registry جایگزین و runbook مستقل از GitHub قابل بازیابی باشد.
- baseline کیفیت شامل TypeScript strict، unit/integration روی PostgreSQL واقعی، contract test از OpenAPI، E2E موبایل/RTL با Playwright، لاگ JSON، correlation ID، OpenTelemetry و synthetic monitoring است.
- سرویس خارجی بدون تأیید کتبی دسترسی تجاری برای ایران، Kubernetes، microservice و استقرار چندمنطقه‌ای وارد baseline نمی‌شوند.

این تصمیم فرض می‌کند هر دو توسعه‌دهنده می‌توانند TypeScript/Node را در سطح تولید نگهداری کنند. اگر پیش از scaffold مشخص شود تیم در NestJS تجربه تولیدی ندارد ولی در Laravel یا Django تجربه معنادار دارد، backend آشنا با همین قرارداد REST/OpenAPI، modular monolith و شکل استقرار جایگزین NestJS می‌شود؛ این تغییر نیازمند بازنگری همین ADR است.

## پیامدها

- خریدار از لینک مستقیم و بدون نصب به مسیر عمومی می‌رسد و تیم یک client اصلی را نگه می‌دارد.
- جدایی web و API یک deployable اضافه می‌کند، اما منطق حساس را از UI جدا و client آینده را ممکن می‌کند.
- PostgreSQL در شروع چند نقش داده، جست‌وجو و صف را دارد؛ عملیات ساده‌تر می‌شود، ولی شاخص‌های contention، عمق صف و p95 جست‌وجو باید دیده شوند.
- انتخاب ارائه‌دهنده داخلی ریسک دسترسی خارجی را کم می‌کند، نه اینکه قابلیت اطمینان را تضمین کند. پیش از production، deploy/rollback، restore زمان‌دار، presigned upload، private network، هزینه خروج و دسترسی از چند شبکه ایران باید آزمایش شوند.
- مرز دقیق ماژول‌ها، schema و state machineها در تصمیم‌های بعدی تعیین می‌شوند؛ این ADR آن‌ها را پیشاپیش تثبیت نمی‌کند.

## بازنگری

این تصمیم در یکی از شرایط زیر باز می‌شود:

- مهارت واقعی تیم فرض TypeScript/NestJS را رد کند؛
- PWA در داده واقعی نتواند نیاز حیاتی device API، upload پس‌زمینه، اعلان یا retention را برآورده کند؛
- p95 جست‌وجو یا contention صف پس از index و tuning از SLO مصوب عبور کند؛
- scale-out چند instance به shared cache یا realtime coordination نیاز پیدا کند؛
- ارائه‌دهنده منتخب restore، خروج داده، SLA یا دسترسی شبکه لازم را در نمونه عملی پاس نکند؛
- الزام قانونی یا قراردادی، محل داده یا شکل استقرار را تغییر دهد.
