# منبع محلی استان‌ها و شهرهای ایران

- تاریخ بررسی: ۱۴۰۵-۰۵-۳۱ (`2026-08-22`)
- پرسش تصمیم: [انتخاب منبع محلی و نسخه‌دار استان‌ها و شهرهای ایران](https://github.com/Mahaan-Amr/sevomart/issues/55)
- نقشه: [[Wayfinder] مسیر سه Spec کالای فیزیکی، خرید و کشف](https://github.com/Mahaan-Amr/sevomart/issues/49)
- وضعیت نتیجه: **بسته با پاسخ منفی؛ فعلاً هیچ dataset رسمی برای کپی، تبدیل و بازتوزیع محلی انتخاب نمی‌شود.**

## پاسخ کوتاه

«[فایل جغرافیایی ـ سال ۱۴۰۴](https://data.gov.ir/datasets/d/af99b547-2495-4c68-a92f-7ed21ac2d8ed)» مرکز آمار ایران در «درگاه ملی کاتالوگ و مجموعه‌داده‌های باز و کاربردی» از نظر مرجع، پوشش و دریافت، بهترین نامزد پیدا‌شده است. فایل XLSX آن استان، شهرستان، بخش، دهستان، شهر و آبادی را همراه کد منتشر می‌کند و برای ساخت فهرست محلی استان/شهر کافی به نظر می‌رسد.

بااین‌حال، metadata همان مجموعه‌داده `license_id`، `license_title` و `license_url` را `null` برمی‌گرداند و پرچم `isopen` نیز `false` است. [تعریف خود درگاه از داده باز](https://data.gov.ir/aboutUs) وجود مجوزی را لازم می‌داند که دسترسی، استفاده، انتقال، تبدیل، هم‌رسانی و استفاده تجاری را اجازه دهد. عبارت عمومی صفحه اصلی درباره «استفاده رایگان و عمومی» به‌تنهایی چنین مجوزی برای کپی، تبدیل و بازتوزیع فایل در مخزن و محصول تعیین نمی‌کند. خود درگاه [فهرست مجوزهای قابل انتخاب](https://data.gov.ir/api/3/action/license_list) دارد، اما ناشر برای این مجموعه هیچ‌یک را انتخاب نکرده است. بنابراین نبود مجوز را اجازه تلقی نمی‌کنیم و فایل نباید فعلاً وارد مخزن، seed یا bundle محصول شود.

رفع مانع به یکی از این دو مدرک نیاز دارد:

1. درج یک مجوز روشن و سازگار با استفاده تجاری، تبدیل و بازتوزیع روی metadata همین مجموعه‌داده؛ یا
2. اجازه کتبی مرکز آمار ایران/مالک داده که صریحاً نگهداری snapshot محلی، تبدیل به قالب محصول و بازتوزیع آن را—همراه الزام انتساب و شرایط به‌روزرسانی—پوشش دهد.

## بازبینی تکمیلی پس از ادغام پژوهش اولیه

[PR پژوهش منبع استان‌ها و شهرهای ایران](https://github.com/Mahaan-Amr/sevomart/pull/61) در `2026-08-22` ادغام شد. بازبینی دوباره metadata رسمی در همان تاریخ تغییر رفع‌کننده‌ای نشان نداد: مجوز همچنان تهی و `isopen=false` است. در عوض، سه فیلد چرخه انتشار اکنون قابل استنادند: `extra_update_rate=سالانه`، `extra_publish_date=2026-07-25` و `extra_revision_date=1405-05-06`. پس cadence سالانه نامزد اصلی روشن‌تر از گزارش اولیه است، اما این metadata جای مجوز یا قرارداد پایداری کد را نمی‌گیرد. checksum فایل نیز تغییر نکرده و جست‌وجوی کاتالوگ هنوز انتشار ۱۴۰۵ یا changelog تازه‌ای نشان نمی‌دهد.

قابلیت دسترسی بدتر شده است: URL منبع ذخیره‌شده در metadata روی `catalog.data.gov.ir` اکنون resolve نمی‌شود، هرچند path معادل روی `data.gov.ir` فایل را می‌دهد؛ پورتال پایگاه ملی تقسیمات کشوری نیز در درخواست‌های مستقیم این بازبینی HTTP 500 داد. این رخدادها تصمیم حقوقی را عوض نمی‌کنند، اما ثابت می‌کنند URL بیرونی حتی برای build/CI منبع پایداری نیست و snapshot تأییدشده باید پس از رفع مجوز به‌صورت محلی نگهداری شود.

سه منبع دارای مجوز روشن نیز از صفحات خودِ مالک داده بررسی شدند. هیچ‌کدام فهرست رسمی و کامل «شهر» در معنای تقسیمات کشوری ایران را عرضه نمی‌کنند:

| گزینه | مرجع و پوشش | دریافت و نسخه‌بندی | مجوز | شناسه | نتیجه و ریسک |
|---|---|---|---|---|---|
| مرکز آمار ایران، فایل جغرافیایی ۱۴۰۴ | ناشر رسمی؛ ۳۱ استان و ۱٬۶۷۲ رکورد نوع شهر در snapshot | XLSX؛ انتشار سالانه؛ UUID مجموعه/منبع و تاریخ انتشار دارد؛ checksum ناشر ندارد | تهی؛ `isopen=false` | کدهای منبع دارد، اما سیاست rename/split/merge/re-parent مستند نیست | **بهترین نامزد، ولی فعلاً غیرقابل vendoring**؛ ریسک حقوقی تعیین‌کننده است |
| [GeoNames](https://download.geonames.org/export/dump/readme.txt) | gazetteer مشارکتی جهانی؛ dump ایران همه featureها را دارد، نه فهرست حقوقی شهرهای ایران | TSV UTF-8؛ dump کشوری، `modifications-<date>` و `deletes-<date>` برای sync روزانه | CC BY 4.0 با سلب تضمین دقت/کامل‌بودن | `geonameid` برای رکورد و admin codeها؛ حذف‌ها جدا منتشر می‌شوند | مجوز و versioning مناسب، اما feature class `P` شهر، شهرک، روستا و دیگر سکونتگاه‌ها را با هم پوشش می‌دهد؛ از ۲۵۴٬۱۵۴ رکورد فعلی ایران، ۸۱٬۸۲۸ رکورد class `P` است و قاعده‌ای برای رسیدن به ۱٬۶۷۲ شهر رسمی نمی‌دهد |
| [OpenStreetMap](https://www.openstreetmap.org/copyright) | داده مشارکتی جهانی؛ `place=*` مستقل از وضعیت اداری نیز برای سکونتگاه‌ها استفاده می‌شود | Planet هفتگی در PBF/XML و diffهای روزانه/ساعتی/دقیقه‌ای؛ extract کشوری نیز ممکن است | ODbL؛ انتساب و share-alike پایگاه مشتق لازم است | `(element_type, id)` و version تاریخچه؛ شیء می‌تواند حذف شود | مجاز و قابل snapshot است، اما [مستندات خود پروژه](https://wiki.openstreetmap.org/wiki/Key:place#Official_place_classifications) می‌گوید طبقه‌بندی اصلی `place=*` بیشتر تمایزهای رسمی کشورها را بیان نمی‌کند؛ برای فهرست قانونی checkout مرجع کافی نیست و تعهدات ODbL نیز از گزینه CC BY سنگین‌تر است |
| [Natural Earth](https://www.naturalearthdata.com/downloads/10m-cultural-vectors/10m-populated-places/) | dataset نقشه‌نگاری جهانی؛ فقط پایتخت‌ها، شهرهای مهم و نمونه‌ای از شهرهای کوچک‌تر | Shapefile نسخه‌دار؛ اکنون `5.1.2` و تاریخچه release/changelog دارد | [Public domain](https://www.naturalearthdata.com/about/terms-of-use/)؛ استفاده تجاری و تغییر مجاز | شناسه‌های dataset، نه شناسه رسمی تقسیمات ایران | از نظر مجوز کم‌ریسک، اما عمداً نمونه‌ای و ناقص است؛ برای checkout رد می‌شود |

نتیجه عملی MVP تغییر نمی‌کند: GeoNames یا OSM را فقط می‌توان برای جست‌وجوی کمکی/اعتبارسنجی غیرقطعی در آینده ارزیابی کرد، نه به‌عنوان منبع حقیقت استان و شهر. تا رفع مجوز منبع رسمی، checkout نباید برای کارکرد پایه به API بیرونی وابسته شود و نباید با dataset ناقص شهرها را رد کند؛ اگر پیاده‌سازی نشانی پیش از رفع blocker لازم شد، نام شهر باید ورودی متنی snapshot‌شونده باشد و اعتبارسنجی سخت فهرست شهر به Issue پس از مجوز موکول شود.

## شواهد منبع‌اول

### ۱. نامزد اصلی: مرکز آمار ایران در درگاه ملی داده باز

[صفحه اصلی درگاه ملی داده باز](https://data.gov.ir/) آن را درگاه واحد گردآوری داده‌های باز دولت جمهوری اسلامی ایران معرفی می‌کند و می‌گوید داده‌های دستگاه‌های اداری را برای استفاده رایگان و عمومی عرضه می‌کند. [metadata ماشینی مجموعه](https://data.gov.ir/api/3/action/package_show?id=af99b547-2495-4c68-a92f-7ed21ac2d8ed) این موارد را ثبت کرده است:

| معیار | یافته |
|---|---|
| مرجع/ناشر | سازمان مجموعه‌داده «مركز آمار ايران» و وضعیت سازمان در کاتالوگ `approved` است. |
| پوشش | عنوان مجموعه «فایل جغرافیایی ـ سال ۱۴۰۴» است. بررسی مستقیم فایل، ردیف‌های نوع استان، شهرستان، بخش، دهستان، شهر و آبادی را نشان داد. |
| قالب و دریافت | یک منبع `XLSX` با اندازه `6,291,221` بایت و شناسه منبع `567b145e-eb48-463d-b334-660bfefb0cff` دارد. [دانلود از دامنه فعال درگاه](https://data.gov.ir/dataset/af99b547-2495-4c68-a92f-7ed21ac2d8ed/resource/567b145e-eb48-463d-b334-660bfefb0cff/download/___) بدون API زمان اجرا ممکن است؛ URL `catalog.data.gov.ir` ثبت‌شده در metadata هنگام بازبینی resolve نشد. |
| زمان انتشار | resource در `2026-07-26` ساخته/ویرایش و metadata مجموعه در `2026-07-28` ویرایش شده است. metadata نرخ به‌روزرسانی را «سالانه»، تاریخ انتشار را `2026-07-25` و تاریخ بازنگری را `1405-05-06` ثبت می‌کند، اما changelog ارائه نشده است. |
| شناسه | فایل ستون‌های کد استان، شهرستان، بخش، دهستان/شهر و آبادی دارد؛ صفرهای آغازین بخشی از کدند. معنای پایداری کد در گذر سال‌ها مستند نشده است. |
| نسخه/تمامیت | `hash` منبع خالی است. برای snapshot دریافت‌شده در این بررسی SHA-256 برابر `4EBF8DE69F64E7634867E096F52346828690DF31975E8638CEC4BF863746C704` محاسبه شد؛ این checksum محلی است، نه checksum اعلامی ناشر. |
| مجوز | `license_id`، `license_title` و `license_url` همگی تهی و `isopen` برابر `false` است. این نقص با وجود پشتیبانی درگاه از مجوزهای داده در [API مجوزها](https://data.gov.ir/api/3/action/license_list) رخ داده است. |

بررسی محتوای snapshot با حفظ مقدار کدها به‌صورت رشته این تعداد را نشان داد:

| `Coderec` | نوع استنباط‌شده از شکل ردیف | تعداد |
|---:|---|---:|
| `1` | استان | ۳۱ |
| `2` | شهرستان | ۴۸۴ |
| `3` | بخش | ۱٬۱۹۳ |
| `4` | دهستان | ۲٬۷۷۷ |
| `5` | شهر | ۱٬۶۷۲ |

۱٬۶۷۲ کد شهر در همین snapshot یکتا بود، ولی فقط ۱٬۶۳۵ نام یکتا وجود داشت؛ بنابراین نام شهر شناسه نیست. این بررسی فقط یکتایی در انتشار ۱۴۰۴ را ثابت می‌کند و دلیلی برای ثابت‌ماندن کد هنگام تغییر نام، ادغام یا جابه‌جایی تقسیماتی در انتشار بعدی نیست. همچنین عنوان بعضی ردیف‌ها مانند «اراک ۱» تا «اراک ۵» نشان می‌دهد که پیش از نمایش مستقیم به خریدار، معنای رکوردهای نوع `5` باید از ناشر تأیید و قواعد پالایش مستند شود.

### ۲. شاهد مرجعیت و چرخه به‌روزرسانی: پایگاه ملی تقسیمات کشوری

گزارش رسمی «[معرفی پایگاه ملی تقسیمات کشوری](https://ncc.gov.ir/uploads/1/2025/Jul/07/%D9%86%D8%B4%D8%B1%DB%8C%D9%87%20%D8%B4%D9%85%D8%A7%D8%B1%D9%87%20122.pdf)» در نشریه علمی و فنی سازمان نقشه‌برداری کشور، شماره ۱۲۲، توضیح می‌دهد که:

- [پایگاه ملی تقسیمات کشوری](https://iransdi.ncc.gov.ir/layersf/irdv) در دسترس عموم است و سالانه به‌روزرسانی می‌شود؛
- اطلاعات آن از مصوبات رسمی گردآوری می‌شود و نقشه‌های خروجی حاوی آخرین اطلاعات مورد تأیید وزارت کشورند؛
- برای پایان ۱۴۰۲، ۳۱ استان، ۴۸۲ شهرستان، ۱٬۱۸۶ بخش و ۲٬۷۶۸ دهستان گزارش شده است.

رابط پایگاه نسخه‌های سال‌های ۱۳۹۷ تا ۱۴۰۳، انتخاب شهر و تولید لینک دانلود مرز را نشان می‌دهد. این منبع برای کنترل تغییرات سالانه و اعتبارسنجی شمار واحدها ارزشمند است، اما در صفحه بررسی‌شده مجوز صریحِ کپی/تبدیل/بازتوزیع داده پیدا نشد و خروجی اصلی آن نیز داده مکانی سنگین‌تری از نیاز checkout است. درخواست مستقیم پورتال در بازبینی تکمیلی HTTP 500 داد. بنابراین نه جایگزین مجاز و کم‌حجم برای فهرست استان/شهر است و نه وابستگی شبکه‌ای قابل اتکا.

[کاتالوگ رسمی وزارت کشور](https://data.gov.ir/api/3/action/package_search?fq=organization:moi&rows=100) نیز جایگزینی منتشر نکرده است: سازمان وزارت کشور در کاتالوگ approved/active است، اما تنها مجموعه پیدا‌شده نامرتبط و بدون resource است. [کاتالوگ سازمان شهرداری‌ها و دهیاری‌ها](https://data.gov.ir/api/3/action/package_search?fq=organization:1829e225d1e1b92c7b435231a5a84ae2b2457199&rows=100) فقط ۱۵ مجموعه استانی «شناسه ملی شهرداری‌ها» دارد؛ پوشش ملی ندارد، مجوز/version آن‌ها تهی است و شناسه حقوقی شهرداری الزاماً شناسه پایدار عنصر جغرافیایی «شهر» نیست.

### ۳. مجموعه شمار تقسیمات برای کنترل معقول‌بودن، نه import

مجموعه رسمی مرکز آمار ایران با عنوان «[تعداد شهرستان، بخش، شهر و دهستان بر اساس تقسیمات کشوری](https://data.gov.ir/api/3/action/package_show?id=cfa40277-1389-4f86-a31e-265e1178f1f5)» فایل‌های XLSX/XLS/TXT قابل دریافت دارد، اما فقط شمارها را منتشر می‌کند و فهرست و شناسه لازم checkout را ندارد. مجوز آن نیز در metadata تهی است. پس فقط می‌تواند پس از رفع مجوز، کنترل جمع آماری انتشار import‌شده باشد.

### ۴. جایگزین‌های دارای مجوز چرا منبع حقیقت نیستند

- [README رسمی dumpهای GeoNames](https://download.geonames.org/export/dump/readme.txt) مجوز CC BY 4.0، TSV UTF-8، dump کشوری، شناسه `geonameid`، تاریخ تغییر هر رکورد و فایل‌های روزانه modification/delete را مستند می‌کند. همان سند feature class `P` را «city, village, ...» تعریف می‌کند و دقت، تازگی و کامل‌بودن را تضمین نمی‌کند. پس schema آن معادل نوع حقوقی «شهر» در تقسیمات ایران نیست.
- [OpenStreetMap](https://www.openstreetmap.org/copyright) اجازه کپی، توزیع و adaptation را زیر ODbL با انتساب و share-alike می‌دهد. [Planet](https://wiki.openstreetmap.org/wiki/Planet.osm) هفتگی و diffها تا سطح دقیقه منتشر می‌شوند؛ [شناسه و version هر element](https://wiki.openstreetmap.org/wiki/Elements#Common_attributes) قابل نگهداری است. بااین‌حال، `place=*` سکونتگاه را مستقل از وضعیت اداری پوشش می‌دهد و مستندات رسمی جامعه OSM تصریح می‌کند که schema اصلی بیشتر تمایزهای قانونی کشورها را بیان نمی‌کند.
- [Natural Earth](https://www.naturalearthdata.com/about/terms-of-use/) داده‌های خود را public domain اعلام می‌کند، ولی [توضیح لایه Populated Places](https://www.naturalearthdata.com/downloads/10m-cultural-vectors/10m-populated-places/) می‌گوید فقط پایتخت‌ها، شهرهای مهم و نمونه‌ای از شهرهای کوچک‌تر را بر اساس اهمیت منطقه‌ای انتخاب می‌کند. versioning خوب، کمبود پوشش را جبران نمی‌کند.

## چرا فعلاً dataset انتخاب نمی‌شود

نامزد مرکز آمار پنج نیاز از شش نیاز را تا حد زیادی پوشش می‌دهد: مرجع دولتی، پوشش ملی، کد، قالب قابل دریافت و انتشار سالانه دارای تاریخ. دو خلأ برای پذیرش باقی است:

1. **مجوز:** هیچ متن یا شناسه مجوزی برای حق تبدیل و بازتوزیع مجموعه ثبت نشده و خود metadata آن را باز اعلام نمی‌کند. «قابل دانلود» یا «رایگان و عمومی» معادل مجوز بازتوزیع نیست.
2. **پایداری هویت:** فایل کد دارد، اما قرارداد ناشر درباره حفظ/تغییر کد در rename، split، merge و re-parent پیدا نشد. یکتایی یک snapshot پایداری میان‌نسخه‌ای را ثابت نمی‌کند.

تا رفع مورد اول، حتی ساختن مشتق JSON و commit آن مجاز فرض نمی‌شود. مورد دوم با قرارداد import محافظه‌کارانه قابل مدیریت است، ولی باید پیش از نمایش همه ردیف‌های نوع شهر، معنای رکوردهایی مانند «اراک ۱» نیز روشن شود. گزینه‌های دارای مجوز روشن یا پوشش رسمی ندارند یا پوشش کامل ندارند؛ بنابراین blocker حقوقی با تعویض عجولانه منبع حل نمی‌شود.

## قرارداد پیشنهادی import و نسخه‌بندی پس از رفع مجوز

این قرارداد وابستگی checkout به شبکه را حذف می‌کند، اما **اجازه واردکردن داده نیست** و فقط پس از دریافت مجوز اجرا می‌شود.

### manifest منبع

هر انتشار یک manifest تغییرناپذیر کنار داده مشتق‌شده داشته باشد:

```yaml
schema_version: 1
source_publisher: "مرکز آمار ایران"
source_dataset_id: "af99b547-2495-4c68-a92f-7ed21ac2d8ed"
source_resource_id: "567b145e-eb48-463d-b334-660bfefb0cff"
source_release: "1404"
retrieved_at: "2026-08-22T...Z"
source_sha256: "4ebf8de69f64e7634867e096f52346828690df31975e8638cec4bf863746c704"
license_id: "مقدار صریح ناشر"
license_url: "نشانی متن مجوز ناشر"
transform_version: 1
```

- URL به‌تنهایی نسخه نیست؛ UUID مجموعه، UUID منبع، release، زمان دریافت و SHA-256 همگی ثبت شوند.
- snapshot خام در CI دریافت نشود. import یک کار نگهداری صریح است و artifact تأییدشده محلی وارد build می‌شود.
- برنامه در runtime فقط dataset محلی را می‌خواند و هیچ fallback شبکه‌ای ندارد.

### شناسه دامنه

- همه کدهای منبع رشته‌اند و صفر آغازین هرگز حذف نمی‌شود.
- `source_key` برابر `SCI_GEO:<record_type>:<source_code>` نگهداری شود؛ برای شهرِ این snapshot، کد رکورد نوع `5` یکتا است، اما این ویژگی در import بعدی دوباره آزموده می‌شود.
- شناسه داخلی `location_id` مستقل، تغییرناپذیر و غیرقابل استخراج از نام یا جایگاه فعلی باشد.
- تطبیق release جدید ابتدا با `source_key` انجام شود. تغییر نام یا والد، هویت داخلی را خودکار عوض نمی‌کند؛ split، merge، حذف یا استفاده دوباره از یک کد نیازمند crosswalk بازبینی‌شده است.
- سفارش snapshot نام و شناسه محل در زمان ثبت را نگه می‌دارد؛ به‌روزرسانی dataset سفارش قبلی را بازنویسی نمی‌کند.

### تبدیل و کنترل داده

- فقط رکوردهای استان و شهرِ مورد تأیید معنایی وارد تجربه نشانی شوند؛ شهرستان و بخش برای parentage/audit نگه داشته شوند، نه لزوماً برای نمایش.
- نام برای نمایش است، نه کلید. نرمال‌سازی «ی/ي»، «ک/ك» و فاصله فقط در فیلد جست‌وجو انجام شود و متن منبع نیز حفظ شود.
- import در schema drift، نوع رکورد ناشناخته، کد تکراری، parent گمشده، نام خالی، حذف گسترده یا تغییر شمار غیرعادی fail شود.
- diff شامل add/rename/re-parent/deactivate/reactivate پیش از انتشار مرور انسانی شود. حذف فیزیکی انجام نشود؛ محل بازنشسته غیرفعال و برای snapshot سفارش قابل resolve بماند.
- release جدید side-by-side وارد و پس از contract/integration test به‌صورت اتمیک فعال شود؛ rollback فقط pointer نسخه فعال را برمی‌گرداند.

## گام دقیق بعدی

بیرون از مقصد فعلی Wayfinder، از مرکز آمار ایران یا مسئول مجموعه در درگاه ملی داده باز درخواست شود که مجوز همان package را در metadata ثبت کند یا اجازه کتبی بدهد. درگاه نشانی `datagov@iran.ir` و شماره‌های `۰۲۱-۸۴۸۰۲۱۱۴` تا `۰۲۱-۸۴۸۰۲۱۱۶` را در [صفحه درباره ما](https://data.gov.ir/aboutUs) برای ارتباط منتشر کرده و metadata مجموعه نام/ایمیل maintainer را خالی گذاشته است؛ بنابراین این کانال رسمی، نقطه شروع قابل پیگیری است.

متن درخواست باید صریحاً این موارد را بپرسد: استفاده تجاری، کپی کامل یا گزینشی، تبدیل XLSX به JSON/SQL، commit یا توزیع مشتق همراه نرم‌افزار، الزام انتساب، امکان نگهداری نسخه‌های قدیمی، معنای `Coderec=5` و رکوردهای شماره‌دار مانند «اراک ۱»، و سیاست کد در rename/split/merge/re-parent. پاسخ باید به UUID package و resource اشاره کند تا به مجموعه دیگری قابل تعمیم نباشد. دریافت چنین پاسخی می‌تواند یک تصمیم تازه برای جایگزین‌کردن ورودی متنی MVP با dataset محلی باز کند؛ این پژوهش فعلی با پاسخ «فعلاً هیچ منبعی انتخاب نمی‌شود» بسته است.
