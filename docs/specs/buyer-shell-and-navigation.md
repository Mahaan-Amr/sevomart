# پوسته خریدار و مسیرهای بازگشت

مرجع اجرا: [تبدیل پوسته خریدار و مسیرهای canonical به تجربه واقعی](https://github.com/Mahaan-Amr/sevomart/issues/123).
این سند تصمیم‌های [معماری اطلاعات](https://github.com/Mahaan-Amr/sevomart/issues/107)
و [پوسته‌های مستقل](https://github.com/Mahaan-Amr/sevomart/issues/111) را در محدوده این برش ثبت می‌کند.

## مرزبندی تأییدشده

مالک مخزن در ۲۸ اوت ۲۰۲۶ تأیید کرد پوسته و هدایت‌های امن اکنون ساخته شوند،
اما مقصدهای ناقص تا تکمیل سفر از ناوبری عمومی پنهان بمانند. بنابراین نمایش چهار
مقصد، وضعیت نهایی پوسته است؛ شرط نمایش هر مقصد، تکمیل تیکت سفر مربوط است.

| مقصد               | مسئول تکمیل سفر                                                                                     |
| ------------------ | --------------------------------------------------------------------------------------------------- |
| کشف و دنبال‌شده‌ها | [ساخت رابط واقعی کشف، دنبال‌شده‌ها و دنبال‌کردن](https://github.com/Mahaan-Amr/sevomart/issues/147) |
| سفارش‌ها           | [ساخت فهرست و پیگیری سفارش خریدار](https://github.com/Mahaan-Amr/sevomart/issues/148)               |
| گفت‌وگوها          | [ساخت فهرست و رشته گفت‌وگوی خریدار](https://github.com/Mahaan-Amr/sevomart/issues/152)              |

ورودی کشف در این برش فقط داده عمومی قرارداد موجود را با شبکه سه‌ستونه و پیوند
کالای موجود نمایش می‌دهد. فید مستقل دنبال‌شده‌ها، دنبال‌کردن در فید و نگهداری
پیشرفته موقعیت پیمایش در تیکت فید باقی می‌مانند. producer، ranking، قرارداد و
مجوزی تغییر نمی‌کند. فعال‌کردن یک مقصد صرفاً کار ناوبری است و مجوز دسترسی نمی‌سازد.

## قواعد پوسته

- سربرگ دسکتاپ فشرده و ناوبری موبایل در پایین است؛ سبد همیشه اقدام سربرگ است.
- پوسته خریدار بر صفحه فروشگاه، کالا یا قدم‌های خرید تحمیل نمی‌شود.
- هویت سوو فقط مقصدهای قابل استفاده را نشان می‌دهد؛ فضای داخلی پلتفرم در آن نیست.
- مسیر ناشناخته پیام فارسی و پیوند قابل استفاده به کشف یا سبد دارد.
- نمونه دورریختنی کشف مسیر عمومی محصول نیست؛ تاریخچه آن در Git حفظ می‌شود.

## مسیرهای امن

`returnTo` و `cancelTo` باید مسیر داخلی معتبر باشند؛ نشانی بیرونی، شکل مبهم
کدگذاری‌شده، نویسه کنترلی، مسیر API و حلقه ورود پذیرفته نمی‌شود. در نبود زمینه
معتبر، بازگشت به کشف انجام می‌شود. هیچ داده نشانی، موبایل، اطلاعات پرداخت یا
متن خصوصی در URL یا ذخیره مرورگر برای نگهداری زمینه قرار نمی‌گیرد.

تغییرهای این برش migration، dependency، متغیر محیطی یا پورت جدید ندارد و
قرارداد producerها و راه‌اندازی Docker/native را تغییر نمی‌دهد.

## گذار مسیرهای موجود

- `/addresses` به `/account/addresses` می‌رود و `returnTo` معتبر را نگه می‌دارد.
- `/checkout` از قدم تحویل شروع می‌شود. `/checkout/delivery` و `/checkout/review`
  همان منطق موجود را در layout مشترک اجرا می‌کنند؛ رفت‌وبرگشت بین قدم‌ها انتخاب‌ها
  را نگه می‌دارد. مرور معتبر فقط در حافظه همان نشست صفحه است؛ ورود مستقیم یا
  refresh مرور، به تحویل و تأیید تازه برمی‌گردد و سفارش یا پرداختی ایجاد نمی‌کند.
- ویرایش نشانی از تحویل به همان قدم برمی‌گردد؛ فقط شناسه روش ارسال و نشانی انتخابی
  در زمینه بازگشت حمل می‌شوند و دوباره با گزینه‌های مجاز پاسخ API تطبیق می‌یابند.
- `/orders/[orderId]?attemptId=…` به `/orders/[orderId]/payment-result` می‌رود و
  همان رسید واقعی را استفاده می‌کند. جزئیات سفارش بدون تلاش پرداخت و مسیر مستقل
  آغاز پرداخت در تیکت سفر سفارش باقی می‌مانند؛ صفحه موقت برای آن‌ها ساخته نمی‌شود.
- پیوندهای فعال داخلی به مقصد canonical اشاره می‌کنند. نامشخص‌بودن رسید یا مسیر
  یک راه برگشت قابل استفاده دارد، نه پیوند به فهرست سفارشی که هنوز ساخته نشده است.
