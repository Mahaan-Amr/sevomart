# قرارداد نسخه اول پرونده اختلاف و پیگیری تخلف

این سند شکل اجرایی بخش «پرونده اختلاف» در
[مشخصات محصول نسخه اول](mvp-product-spec.md) را برای subpath مالک
`@sevo/contracts/problem-follow-up/v1` ثبت می‌کند. قرارداد این Issue فقط seam
نسخه‌دار، fragment مالک OpenAPI، رخداد و audit را تثبیت می‌کند؛ persistence و
runtime producer در Issue مستقل ساخته می‌شوند.

## مهلت‌ها و eligibility

- فقط خریدار همان سفارش می‌تواند پرونده را باز کند.
- بازه ثبت تا ۷ روز تقویمی پس از تحویل است؛ اگر تحویل ثبت نشده باشد تا ۱۴ روز پس
  از ارسال باقی می‌ماند.
- نخستین پاسخ فروشنده حداکثر ۴۸ ساعت پس از ثبت پرونده است.
- عامل پلتفرم فقط تا ۷ روز پس از نتیجه و با مدرک تازه و دلیل ثبت‌شده می‌تواند
  پرونده حل‌شده یا بسته‌شده را بازگشایی کند.
- زمان‌ها از snapshot authoritative سفارش و انجام سفارش محاسبه می‌شوند و ورودی
  قابل اعتماد client نیستند.

## state و transition

وضعیت‌های نسخه اول `DRAFT`، `SUBMITTED`، `AWAITING_SELLER_RESPONSE`،
`UNDER_REVIEW`، `RESOLVED` و `CLOSED` هستند. draft و submit می‌توانند در رابط و
ثبت اتمیک producer یک قدم دیده شوند؛ عملیات `OpenDispute.v1` پس از ثبت موفق
پرونده را مستقیماً در `AWAITING_SELLER_RESPONSE` قرار می‌دهد، deadline پاسخ
فروشنده را می‌سازد و رخداد `DisputeOpened.v1` را منتشر می‌کند.

گذارهای عملیاتی عمومی محدودند:

- `OPEN`: فقط خریدار، از نبود پرونده به `AWAITING_SELLER_RESPONSE`؛
- `RESPOND`: فقط فروشنده همان فروشگاه، از `AWAITING_SELLER_RESPONSE` به
  `UNDER_REVIEW`؛
- `RESOLVE`: فقط عامل دارای مسئولیت و دسترسی زنده، از `UNDER_REVIEW` به
  `RESOLVED` یا `CLOSED`؛
- `REOPEN`: فقط عامل دارای مسئولیت و دسترسی زنده، از `RESOLVED` یا `CLOSED` به
  `UNDER_REVIEW` و در بازه هفت‌روزه.

وضعیت توصیفی پرونده تخلف از state سفارش و پرونده اختلاف مستقل است. منبع آن
می‌تواند پرونده اختلاف، سفارش یا گزارش عملیاتی باشد، اما این قرارداد برای تخلف
state machine یا transition تازه تثبیت نمی‌کند و هیچ پیگیری آن وضعیت سفارش یا
پرداخت را تغییر نمی‌دهد. seam نسخه اول فقط ثبت `ViolationRecorded.v1`، صف و نمای
پرونده کمینه و audit پیگیری را منتشر می‌کند؛ رفتار producer در Issue ساخت خودش
به تصمیم محصول محدود می‌ماند.

## دسترسی کمینه

- خریدار فقط پرونده سفارش خودش، contributionهای رسمی، deadline، مسئول قدم بعدی
  و نتیجه را می‌بیند.
- فروشنده فقط پرونده سفارش همان فروشگاه و داده لازم برای پاسخ را می‌بیند؛ شماره
  موبایل، نشانی یا داده نامرتبط خریدار جزو contract نیست.
- عامل با مسئولیت `DISPUTE_REVIEW` یا `VIOLATION_REVIEW` ابتدا صف کم‌جزئیات را
  می‌بیند. شرح و مدرک فقط با اجازه حساس فعال همان پرونده و در حالت
  `REVEALED_MINIMUM` آشکار می‌شود.
- actor ورودی HTTP نیست. adapter آن را از نشست هویت یا عامل می‌سازد و command
  داخلی literal جایگاه همان operation را اعتبارسنجی می‌کند.

## مدرک، رخداد و audit

مدرک در پرونده مالک با شناسه opaque، نوع و زمان نگهداری می‌شود. محتوای فایل، شرح
پرونده و شناسه مدرک در event، صف کم‌جزئیات یا audit کپی نمی‌شوند. رخدادها فقط
شناسه پرونده/سفارش/فروشگاه، وضعیت، deadline و reason code بسته را حمل می‌کنند.

audit append-only هر transition، actor، زمان، correlation، reason code و فقط شمار
مدرک را ثبت می‌کند. log عملیاتی مجاز نیست متن contribution، مدرک، شماره موبایل،
نشانی یا داده بانکی را ثبت کند.

## HTTP و سازگاری

OpenAPI مسیرهای جدا برای خریدار، فروشنده و عامل پلتفرم دارد. همه mutationها
`Idempotency-Key` می‌خواهند. نبود منبع یا نبود مالکیت مرتبط برای خریدار/فروشنده
با `404` بدون افشای وجود پرونده پاسخ می‌گیرد؛ نبود مسئولیت یا اجازه حساس عامل
`403` است. deadline یا transition نامعتبر و replay ناسازگار `409` هستند.

این قرارداد فقط از subpath مالک منتشر می‌شود. package root، composer مرکزی،
registry composition و migration ledger تغییر نکرده‌اند. تغییر این Issue runtime،
schema پایگاه داده، dependency تازه یا مسیر startup ندارد؛ بنابراین بررسی Docker
و native به build/typecheck/contract composition محدود است و migration تازه‌ای
وجود ندارد.
